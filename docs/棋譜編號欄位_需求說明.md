# 成績資料增加「棋譜編號」欄位　需求說明

**提出者**：中華職業圍棋協會 秘書處
**對象**：成績系統（棋賽賽程操作台）維護者
**日期**：2026-11-04

---

## 一、想做的事

職協官網的「我的成績」會列出棋士今年的每一局：

```
10.30  勝
黑：李維　白：賴均輔　白3.5目勝
中環碁聖賽・本賽8強
```

希望每一局後面能加一個「看棋譜」的連結，點了直接開 HiGO 的那一局：

```
https://www.higohigo.org/#/kifu/43278
```

目前做不到，因為成績資料裡沒有棋譜編號，官網無從判斷某一局對應哪一份棋譜。

## 二、希望怎麼改

成績資料 `results/y{年}` 的 `rows`，目前每一局是固定 9 格的陣列：

```json
["10.30","國內","正式","中環碁聖賽","本賽8強","李維","賴均輔","賴均輔","白3.5目勝"]
```

**請在最後面加第 10 格，放 HiGO 的棋譜編號（字串）：**

```json
["10.30","國內","正式","中環碁聖賽","本賽8強","李維","賴均輔","賴均輔","白3.5目勝","43278"]
```

| | 內容 |
|---|---|
| 位置 | **陣列的最後一格（索引 9）** |
| 型別 | 字串 |
| 值 | 棋譜網址 `https://www.higohigo.org/#/kifu/43278` 最後那串數字，即 `"43278"` |
| 沒有棋譜時 | 空字串 `""`（或整格省略亦可） |

## 三、為什麼一定要加在最後面

現在讀這份資料的程式（包含貴系統自己的查詢頁、職協官網）都是**依位置**取值的：
第 1 格是日期、第 6 格是黑方……。若插在中間，後面每一格都會錯位，所有讀取端
同時壞掉，而且不會報錯——只會悄悄顯示錯的資料。

加在最後面則**完全相容**：舊程式只讀前 9 格，多出來的那格會被忽略，
不必同步改版，也不必擔心漏掉誰。

## 四、舊資料不必回頭補

有編號的填上去，沒有的留空即可。職協官網會自行判斷：**有編號才顯示連結，
沒有就不顯示**，不會出現點了是空白的連結。

## 五、官網這邊已經準備好

職協官網已經改成會讀第 10 格（2026-11-04 上線）。**貴系統哪天加上去，
官網當天就會自動出現「看棋譜」連結，不需要另行通知，也不必等我們改版。**

為了安全，官網只接受純數字的編號，其餘一律當作沒有棋譜。

## 六、如果不方便加在同一份資料

也可以改成另外一份對照表（例如 `results/kifu-y2026`），內容是
「對局 → 棋譜編號」。只是這樣兩邊都要多做比對的工作，建議優先考慮第二節的做法。

若貴系統已經有其他地方可以查到對局與棋譜的對應關係，也請告知，我們直接讀那裡。

## 後續（2026-11-10，秘書處補記）

對方沒有在 `rows` 加第 10 格，而是**另外做了一份對照表**：用「年份｜日期｜黑方｜白方」
把每一局配到 HiGO 的公開棋譜，檔案放在
`https://milu891212-milu.github.io/qisai-schedule-web/results/higo.json`，
成績查詢頁讀那一份顯示「棋譜」欄。

官網配合改成讀同一份對照表，但**不即時連對方的站**：每天在 CI 抓一份放進
`site/assets/data/kifu.json`（`scripts/fetch_kifu.py`，只留最近三年），
網頁讀自己網域的檔案。`results.js` 仍保留第 10 欄的支援，對方哪天真的加上去就會優先採用。

當天實測：賴均輔 2026 年 130 局中有 128 局配得到棋譜。配不到的多半是對方尚未上傳棋譜。
同一天同一對下兩盤時對照表會給兩個編號，官網兩個都列（「看棋譜 1 / 看棋譜 2」）——
對照表只有日期與雙方姓名，分不出哪一盤是哪一份。
