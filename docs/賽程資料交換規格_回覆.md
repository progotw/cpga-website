## Q2. 同一天上午、下午各一局

### 時間要填什麼

**上午填 `10:00`，下午填 `14:00`。**

這不是我們隨便訂的，是從海峰的抽籤公告統計出來的。目前官網解析到的 162 組對局裡：

| 時間 | 筆數 |
| --- | --- |
| `10:00` | 66 |
| `14:00` | 10 |
| 空白 | 86 |

而且同日雙局實際存在，公告寫的就是這兩個值，例如 2026-04-27 的快棋爭霸戰，林宇翔、陳劭全等 10 位棋士都是 10:00 一局、14:00 一局。

**更正一件事**：規格 v1.0 寫「留空時官網會套慣例（一般 11:00）」，那是寫錯的 —— 官網其實不會自行補值，留空就是畫面上不顯示時間。11:00 這個數字沒有根據，已經從規格裡拿掉。所以**請盡量填實際值**，真的不確定才留空。

### 會不會被當成重複或衝突

**原本會，這是你們這個問題幫我們抓到的 bug，已經修掉了。**

官網比對衝突的方式是：以「同一天、同一位棋士」為鍵，比較兩邊記錄的對手。原本的判斷是「兩邊的對手集合不相等就算衝突」。

問題在於：如果公告只貼了上午那局、你們兩局都有，那麼

```
公告   林宇翔 → {黃彥誠}
操作台 林宇翔 → {黃彥誠, 陳劭全}
```

集合不相等 → 被誤判為衝突 → **兩局都不顯示**。但這其實不是矛盾，只是涵蓋範圍不同。

改成「**互相不包含才算矛盾**」：

```python
# 只有兩邊互相不包含才算矛盾。
# 同一天上下午兩局時，公告可能只貼了其中一局，
# 若用「集合不相等」判斷，會把這種涵蓋範圍不同誤判成衝突。
if opps_a and opps_f and not (opps_a <= opps_f or opps_f <= opps_a):
```

測過四種情況：

| 情況 | 結果 |
| --- | --- |
| 公告只有上午、操作台有上下午 | 不算衝突，兩局都保留 ✓ |
| 兩邊對手真的不同 | 仍判定衝突，三人全部剔除 ✓ |

所以：**兩筆都不帶 `time` 也不會出事**，但帶上去對棋士比較有用。

## Q3. 雙棄權

**那一局照輸出，`winner` 省略或填 `null`。** 有這筆資料，官網就知道這兩位結束了。

**下一輪的輪空請不要輸出。**

這點我們要更正規格 v1.0 ——它寫「輪空：`players: [X, null]`，`round` 寫「輪空」」，那是錯的。理由是「我的賽程」這個功能的用途是回答「**我什麼時候要到場**」。輪空沒有要下的棋，顯示出來等於通知棋士那天要去，結果白跑一趟。

所以規則是：

| 情況 | 輸出？ | 為什麼 |
| --- | --- | --- |
| 對手未定（上一輪還沒下完） | ✅ 輸出 `[X, null]` | 那天**確實要下棋**，只是不知道跟誰 |
| 輪空 | ❌ 不輸出 | 那天**不用來** |

這兩件事在資料上長得很像，但對棋士的意義完全相反。

官網這邊也加了防呆：`round` 含「輪空」的會被略過，萬一不小心輸出了也不會害人白跑。

## Q5. 非職業棋士的姓名 —— 選項 2，全部輸出

**請全部輸出，對不上名錄的由我們略過。**

理由：

- 官網本來就有姓名比對的機制（抽籤公告也是混著各種賽事解析的），略過對不上的是既有行為
- 你們少一個「要判斷哪些賽事算職業」的維護負擔，那個判斷會隨時間變動
- 協會之後若要顯示業餘賽事，資料已經在，不必再來談一次

**一個小提醒**：如果業餘選手裡有人跟職業棋士同名，理論上會產生假的對局。這個風險很低，而且你們說會把對不上名錄的姓名列出來給我們，我們可以從那份清單看出端倪。

## 關於日期缺口

你們說多數賽事的日期印在底圖圖片上、不是資料，要新增一個「每輪日期／時間」的設定讓賽務同事填。

**這個順序是對的，不用等填完才上線。** 官網的設計本來就假設兩邊涵蓋範圍不同：

| 情況 | 官網行為 |
| --- | --- |
| 只有你們有 | 顯示 |
| 只有公告有 | 顯示 |
| 都有且一致 | 顯示 |
| 都有但矛盾 | 不顯示，列入待確認 |

**某一邊沒資料不算衝突**，是常態。所以先輸出有日期的輪次，其餘等同事陸續補，官網會自動跟著變多，不會因為資料不全而壞掉。
