# 賽程資料交換規格

給「棋賽賽程操作台」（`qisai-schedule-web`）維護者的需求說明。

中華職業圍棋協會官網的棋士專區要顯示「我的賽程」—— 每位棋士登入後只看到
自己接下來還要下的對局。目前官網是從海峰的「抽籤結果公告」解析純文字取得
對戰組合，但那有兩個死角：

1. 對陣文字沒貼到官網的那一輪，就抓不到
2. 對陣表只放在圖片裡的公告，無法解析

操作台是這份資料的上游（它本來就有「產生對陣文字（給官網用）」的功能），
若能直接取得，官網就能**兩邊交叉比對**：一致才顯示，不一致就標記出來請人確認，
而不是默默顯示可能錯誤的對手與時間。

---

## 需要做的事（擇一即可）

### 方案 A：輸出一份公開可讀的 JSON（建議）

在「封存／發布」時，額外把目前賽程寫成一份固定網址的 JSON。例如：

- 寫進 GitHub Pages 的同一個 repo，網址 `https://<帳號>.github.io/qisai-schedule-web/public/pairings.json`
- 或寫進 Firestore 另一個集合（例如 `public_pairings`），安全規則設為
  `allow read: if true; allow write: if request.auth != null;`

**只需要包含下列欄位，不要包含任何個資。**

### 方案 B：給官網一組唯讀憑證

若不想公開，可在 Firebase 另建一組唯讀的安全規則與服務帳號，
官網的每日排程會用它讀取。憑證由協會保管並貼進 GitHub Secrets，
不會出現在任何網頁原始碼裡。

方案 A 比較單純，也不必管理憑證，建議優先。

## 資料格式

```json
{
  "updated": "2026-10-02T14:30:00+08:00",
  "pairings": [
    {
      "event": "第20屆棋王賽",
      "round": "資格賽",
      "date": "2026-09-22",
      "time": "10:00",
      "players": ["徐銘均", "林聖弈"],
      "winner": "林聖弈"
    },
    {
      "event": "第20屆棋王賽",
      "round": "初賽1回",
      "date": "2026-09-29",
      "time": "10:00",
      "players": ["林彥丞", null]
    }
  ]
}
```

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `event` | ✓ | 賽事名稱。沿用操作台現有的名稱即可，不需配合官網用字 |
| `round` | ✓ | 輪次，例如「資格賽」「初賽1回」「本賽二回戰」 |
| `date` | ✓ | 對局日期，`YYYY-MM-DD` |
| `time` |  | 開賽時間，`HH:MM`。留空時官網會套用慣例（一般 11:00） |
| `players` | ✓ | 兩位棋士的**姓名**，不含段位或頭銜。對手未產生時填 `null` |
| `winner` |  | 已下完的對局填勝方姓名；未下完省略或填 `null` |

### 兩個重點

**姓名不要帶段位或頭銜。** 官網是用姓名跟棋士名錄對應的。
操作台內部若存「賴均輔 碁聖」，輸出時請只給「賴均輔」。

**`winner` 有填的話，官網能做得更好。** 目前官網是靠「沒有新的對戰組合」
推論棋士已被淘汰；有了勝負就能直接判斷，也能顯示個人戰績。沒有也不影響基本功能。

## 官網這邊會怎麼處理

| 情況 | 官網的行為 |
| --- | --- |
| 兩邊都有且一致 | 正常顯示 |
| 只有操作台有 | 顯示，標示資料來源 |
| 只有官網公告有 | 顯示，標示資料來源 |
| 兩邊**對手或日期不一致** | **不顯示**，並在協會後台列出差異請人確認 |

最後一種是這個規格存在的主要理由：棋士會依照這份資料安排當天行程，
顯示錯誤的對手或時間比顯示不足更嚴重。

---

## 不需要做的事

- 不需要即時同步。官網每日更新一次，有需要時協會也可手動觸發
- 不需要改動操作台現有的任何畫面或流程
- 不需要提供選手聯絡方式、身分資料或任何個資
- 不需要提供歷史資料，當年度進行中的賽事就夠
